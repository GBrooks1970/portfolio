## Outcome

The landing page has a 'Learning Paths' link in its hero, next to 'Latest Code Reviews Index', that opens
`learning-paths.html`: a pinned snapshot of the Learning Paths document. The change is on a branch and not
merged, so the live page does not yet show it.

## Scope

- Non-goals: cards, registry, sitemap, robots, and the source repository.

## Decisions

- **A pinned copy, not a link to the source.** The source repository is private (`private: true`,
  `has_pages: false`), so a link would 404 for visitors and fail the external-URL gate. The owner was asked and chose
  the pinned copy over making the repository public or holding the change.
- **Same pattern as `reviews.html`.** The snapshot holds already-rendered HTML, so no Markdown dependency is added
  (`requirements-dev.txt` has only PyYAML), and a drift check compares the committed page with the render.
- **Private links become text.** The document links two files in the private repository. The generator turns them
  into plain text and rejects any link form it does not know, rather than publishing dead links.
- **Hero link, not a card.** Learning Paths is not a project, so it does not belong in the registry-governed card
  groups. The hero already carries the reviews link.
- **Priority P2:** an enhancement, not an accuracy defect. The owner may re-rank.

## Failures and recovery

The interactive-element and internal-reference counts in `test_site_quality.py` are pinned, so the new link
failed two assertions in turn. Both were expected consequences of adding a link and were updated to 66 and 7.

## Durable lessons

- Check a link target's visibility before linking it from a public page. This repository's source of the
  document is private.
- Pinned counts in the quality test mean any new hero or card link needs a deliberate baseline update.
- The snapshot cannot be drift-checked against its private source in CI, so refreshing it is a manual step.
